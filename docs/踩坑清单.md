# 全流程踩坑清单

> 来源：一次真实的 HP Pavilion 14-ce0xxx 装机（2026-11-15 ~ 11-18）。
> 机器：i5-8250U / UHD 620 / 8GB / KBG30ZMV256G NVMe / Intel 9560 / ALC295 / Synaptics
> 结果：macOS Ventura 13.7.8 + OpenCore 1.0.9，单系统日常使用
>
> 下面每一条都写清「现象 → 根因 → 处置 → 教训」。换机器时结论要重新验证，但**判断方法和坑的形状是通用的**。

---

## 〇、一页速查：下次装机必做的 12 件事

- [ ] **1. 装完立刻把 OpenCore 拷进硬盘 EFI**，拔 U 盘能开机才算装完
- [ ] **2. 确认 `EFI/OC/OpenCore.efi` 在硬盘上**，不是只有 `EFI/BOOT/BOOTx64.efi`
- [ ] **3. `Misc > Boot > LauncherOption = Bootstrap`**，让 OC 自己注册启动项
- [ ] **4. BIOS：UEFI、Secure Boot 关、Fast Boot 关、VT-d 可留**
- [ ] **5. USB 端口做真实映射**（≤15 口，蓝牙/摄像头标 Internal，Type-C 标 9）
- [ ] **6. 蓝牙 kext 顺序**：Lilu → IntelBluetoothFirmware → IntelBTPatcher → BlueToolFixup
- [ ] **7. 改完蓝牙 kext 必须完全关机冷启动**，不要热重启
- [ ] **8. 声卡 layout 要逐个试**（ALC295 这台是 24，不是 14）
- [ ] **9. 手动设时区**，关掉「自动设置时区」（Intel 网卡没有定位）
- [ ] **10. 睡眠参数检查**：`pmset -g custom` 别出现 `sleep 1`
- [ ] **11. 系统更新别走 OTA**，也别用磁盘工具"急救"修系统宗卷
- [ ] **12. 留一张能启动的 U 盘**，这是唯一的救命盘

## 阶段 0 · 可行性判定：一开始就会走错的三条路

### A01 · 拿 Stela 当"PC 变 Mac"的工具

**现象**：项目描述看起来像"把 PC 变成苹果系统"，装完发现图形完全不工作。

**根因**：Stela 只处理 NVIDIA 显卡的老平台（Maxwell/Pascal 时代的 Web Driver），
对 Intel 核显机器没有任何意义。本机只有 UHD 620，天然不适用。

**教训**
> 判据是「**图形能不能被驱动**」，不是「工具支不支持 PC」。
> 只有核显的机器走 WhateverGreen + iGPU；只有 NVIDIA 独显的机器（12 代以后）直接放弃。

### A02 · 把 OpenCore-Legacy-Patcher 当成黑苹果工具

**根因**：OCLP 是给**真 Mac**（2007 年起的旧苹果机器）打补丁跑新系统用的，
它依赖苹果固件、原厂 SMC、原厂硬件。普通 PC 上它既找不到目标机型，也没有可打的补丁。

**教训**
> 两条完全不同的技术路线：
> - **真 Mac 解锁新系统** → OCLP
> - **PC 装 macOS** → OpenCore + OpCore-Simplify（生成 EFI）+ WhateverGreen/Lilu 这套 kext
>
> 混用 = 一天白干。

### A03 · "这台机器能不能装"只回答"能"或"不能"

**根因**：可行性是分层的——能不能装、装了能不能用、哪些功能注定没有。
只答"能"，用户会在装完之后才发现不能隔空投送、没有定位、没有 Type-C 视频输出。

**处置**：按三层给结论（见 `macplan/compat.py`）：
1. 硬门槛：CPU 代次 + 图形是否可驱动
2. 体验层：Wi-Fi 形态（itlwm 无原生菜单）、蓝牙共存、读卡器
3. 明确劝退项：无核显且无受支持 A 卡 / 11 代以后无解的组合

## 阶段 1 · 启动盘制作：翻车最密集的一段

### B01 · U 盘容量：6.67GB 是不够的

**现象**：格式化对话框显示容量 `6.67 GB`，写入到一半空间不足。

**根因**：标称 8GB 的盘，实际可用 7.4GiB 左右；恢复镜像（BaseSystem.dmg 约 670MB）
+ EFI（37MB）+ 后续可能追加的完整安装包（Ventura 约 12GB），6.67GB 的盘连镜像都紧张。

**教训**
> 门槛写死在工具里：**≥7.4GiB 才放行**。想以后能放完整安装包，直接上 16GB。

### B02 · 旧 U 盘的 FAT 目录项损坏 → 删不掉、也写不进

**现象**：
- 目录看着是空的，实际有 211 个目录项；
- `Remove-Item -Recurse -Force` 报错，`[IO.Directory]::Delete` 也失败；
- 用 robocopy 镜像空目录"清空"，只清掉了数据，留下 71 个空壳目录；
- `.NET` 复核：211 个目录 / 0 个文件。

**根因**：这块盘以前被手机/PE 工具反复写过，FAT 表里的目录项与实际数据区不一致，
Windows 的资源管理器按目录项走，于是一直显示"空但删不掉"。

**处置**：只能整盘重建分区表（磁盘管理里删除卷 → 新建简单卷 → 格式化 FAT32）。
工具侧的做法是先做**可写性探针**（写一个 1KB 临时文件再删），探针失败直接拒绝这块盘。

**教训**
> 不要相信"资源管理器显示空"。要相信**能不能写进去**。

### B03 · 格式化被系统拦下，提权也失败

**现象**：调用格式化接口返回"严禁自动执行格式化操作"，`Start-Process -Verb RunAs` 提权被拒
（pid 19028, exit 1，无日志）。

**根因**：这是**助手侧的安全限制**，不是 Windows 的限制。真正的解决方法是由**用户本人在资源管理器里格式化**。

**教训**
> 工具不该偷偷格式化。MacPlan 的设计是：探测 → 提示 → 让用户自己确认（输入 `YES`）→ 再执行，
> 并且只允许对 **USB 总线、非系统盘、≥7.4GiB** 的磁盘动手。

### B04 · GitHub API 403：拿不到最新版本号

**现象**：想自动查 OpCore-Simplify 最新 release，`api.github.com` 返回 403 rate limit。

**处置**：不要依赖 API。用**固定版本 + 压缩包直链**：
`https://github.com/lzhoang2801/OpCore-Simplify/archive/refs/tags/<tag>.zip`，
版本号用环境变量 `MACPLAN_OPCORE_TAG` 可覆盖。这样构建可复现，也不怕限流。

### B05 · 自动应答 OpCore-Simplify 的菜单，一不小心就死循环

**现象**：脚本喂空回车，工具反复打印同一个菜单，直到超时。

**根因**：OpCore-Simplify 是纯交互式菜单，个别分支空回车的语义是"重新显示菜单"而不是"用默认值"。

**处置**（`macplan/efibuild.py` 的做法）：
- 用规则表按**提示词片段**匹配答案，而不是按顺序盲喂；
- 每次应答都写进 `macplan_answers.log`，失败时能直接看出卡在哪个问题；
- 版本固定，菜单变了就更新规则表，而不是靠猜。

**教训**
> 驱动别人的交互式 CLI，必须留"问答日志"。没有日志的自动化 = 不可维护。

### B06 · U 盘卷标是中文 → OpenCore 菜单里显示成 `___U___(dmg)`

**现象**：按空格展开隐藏项后，出现一个橙色齿轮图标，名字是一串下划线。

**根因**：OpenCanopy 的主题字体没有中文字形，中文卷标全部渲染成下划线，只剩扩展名可读。

**处置**：卷标强制 ASCII（`MACBOOT`），工具里直接校验"≤11 位且全是 ASCII"。

**教训**
> 橙色齿轮 = DMG 恢复项，不是坏了。但名字认不出来会让人以为引导失败。

### B07 · `DmgLoading = Signed` → 恢复项根本不显示（本次最隐蔽的坑）

**现象**：EFI、镜像、U 盘全都正确，OpenCore 菜单里就是没有 macOS 安装项。

**根因**：`Misc > Security > DmgLoading` 默认 `Signed`，会对 DMG 做签名校验；
自制/下载的恢复镜像过不了校验时，**这一项会被静默过滤掉，连错误提示都没有**。

**处置**：安装期一律 `Any`。

### B08 · `ScanPolicy` 非 0 → U 盘上的安装项被过滤

`ScanPolicy = 0` 表示扫描所有设备。非 0 的位掩码会排除外部设备/HFS 卷，
结果就是"U 盘插着、EFI 也对，菜单里只有 Windows"。

### B09 · `SecureBootModel = Default` 在安装期会挡路

装完可以改回 `Default`，但**安装阶段必须是 `Disabled`**，否则恢复环境起不来。

### B10 · USB 2.0 口 vs 3.0 口

**现象**：两个口都试了，引导行为不一致（一个能进菜单，一个黑屏重启）。

**处置**：优先用 **USB 3.0 口（通常是蓝色/带 SS 标识）**，并且**不要经过 Hub**。
部分 HP 机型的 USB2 口在 OpenCore 阶段枚举不稳定，装完系统后才正常。

### B11 · 分配单元大小 4096 字节对不对

**答案：对。** FAT32 在 32GB 以下默认就是 4096 字节，改大反而浪费、且老固件兼容性差。
真正要紧的是**文件系统必须是 FAT32**（不是 exFAT），因为 UEFI 固件只认 FAT。

### B12 · 写完不校验，装到一半报错

**现象**：拷贝过程没报错，安装到 60% 提示镜像损坏。

**处置**：写完必须做三件事（`macplan/verify.py`）：
1. 源/目标**逐文件 SHA256** 比对（141 个文件 / 36.8MB 全等）
2. `BaseSystem.dmg` 尾部 `koly` 魔数 + 体积下限
3. `EFI/OC/OpenCore.efi` 体积区间、`EFI/BOOT/BOOTx64.efi` 不能是 1.6MB 的 Windows 启动器

### B13 · 单系统 vs 双系统：不是"分区"问题，是"抹盘"问题

**结论**：单系统 = 用「磁盘工具」把**整块硬盘**抹成 APFS/GUID，Windows 一起消失。
想保留 Windows 就必须先缩容、留出未分配空间，再让 macOS 自己建容器——多出来的每一步都是坑。

**教训**
> 装之前先确认盘里没有要留的数据。工具在向导里会把这句话要求二次确认。

## 阶段 2 · 引导与 EFI

### K01 · 硬盘 EFI 分区里根本没有 OpenCore（本次最大的坑）

**现象**
```
$ sudo diskutil mount disk0s1 && ls /Volumes/EFI/EFI/OC
ls: /Volumes/EFI/EFI/OC: No such file or directory
```
分区里只有旧 Windows 残留：`EFI/Microsoft/Boot/bootmgfw.efi`、`BCD`，
以及 `EFI/Boot/bootx64.efi`（1.6MB，其实是 Windows 的 bootmgfw，不是 OpenCore）。

**根因**：一直靠 U 盘引导，从没把 EFI 拷进硬盘 ESP；而厂商文档假设"ESP 是干净的"。

**解决**
1. 备份 ESP 原内容；
2. 删掉 `EFI/Boot`、`EFI/Microsoft` 残留；
3. 把 U 盘的 `EFI` 完整拷进 ESP 根目录；
4. `EFI/BOOT/BOOTx64.efi` 必须是 OpenCore 启动器（约 24KB）。

**教训**
> 判断"引导在不在硬盘上"：看 ESP 里有没有 `EFI/OC/OpenCore.efi`（约 600KB）。
> `nvram efi-boot-device` 指向 Preboot 是**正常现象**，不能证明 OC 在硬盘。

### K02 · OpenCore 不自动注册启动项，每次都得按 F9

**根因**：`Misc > Boot > LauncherOption = Disabled`（默认）。

**解决**：改 `Bootstrap`（`LauncherPath = Default`）+ `RequestBootVarRouting = true`。

> ⚠️ `bless --setBoot` 在这台 HP 上不可用：`Could not set boot device property: 0xe00002e2`。
> 没有启动项时 F9 只能进 BIOS 文件浏览器手翻 `EFI/OC/OpenCore.efi` —— 这不是引导坏了。

### K03 · ESP 只有 105MB，别塞多余东西

OpenCore + 21 个 kext 约 37MB，加旧 Windows 残留 27MB 刚好够。清完剩 58MB。
**主题资源、图标包不要往 EFI 里塞**。

## 阶段 3 · 安装过程

### I01 · 抹盘格式选错

必须 **APFS + GUID 分区图**。选 Mac OS 扩展（日志式）会装完起不来。

### I02 · 安装中途重启，选错启动项

安装会重启 2~3 次，每次都要从 OpenCore 菜单里选**同名的 macOS 安装项**（不是 U 盘的恢复项），
装完才出现硬盘上的系统项。中途拔 U 盘 = 前功尽弃。

### I03 · 安装期间断电 / 合盖休眠

笔记本装系统时把电源接上、盖子打开、电源管理里关掉休眠。

## 阶段 4 · 驱动：全部是"设备在、功能死"的坑

### K04 · Wi-Fi：itlwm 通了，但没有 HeliPort，密码还明文写在 kext 里

**现象**：能上网，但系统里没有 Wi-Fi 界面，网络设置显示成"以太网"；
`ioreg -r -c itlwm -l` 能看到 `WiFiConfig`，含 5 组 SSID + **明文密码**。

**根因**：itlwm 是"以太网形态"的驱动，不做原生 Wi-Fi 界面；
厂商为了方便，把账号密码直接写进 `itlwm.kext/Contents/Info.plist`。

**解决（顺序不能反）**
1. 装 HeliPort 1.5.0 → `/Applications`，加登录自启；
2. 在 HeliPort 里连一次网络；
3. **再**把 `WiFiConfig` 整个字典删掉（先连上再删，否则重启就没网）；
4. 密码建议全部改一遍（EFI 在 FAT32 上明文可读，谁拿到盘都能看到）。

### K05 · USB 端口没有真正映射（USBToolBox 在，map 是空壳）

**现象**：`USBToolBox.kext` 加载了、`UTBDefault.kext` 也在，但所有端口都没有 `UsbConnector` 属性。

**根因**：`UTBDefault.kext` 只是"默认空壳"，里面没有端口数据。

**解决**：自制 `UTBMap.kext`（USBToolBox 格式）：
- 15 个端口全部保留；
- **蓝牙（端口 7）、摄像头（端口 3）标 255 (Internal)**；
- **Type-C 的 USB2 侧（HS04）标 9 (Type-C)**；
- 其余标 3 (USB3)。

**教训**
> Ventura 上 `XhciPortLimit` 补丁已失效，端口总数必须 ≤15；
> Internal 类型对蓝牙睡眠唤醒稳定性有直接影响。

### K06 · 蓝牙唤醒后崩溃循环（25 次 bluetoothd 崩溃）

**现象**：`/Library/Logs/DiagnosticReports/` 里 25 个 `ExcUserFault_bluetoothd-*.ips`，
集中在 23 分钟内，`EXC_GUARD / GUARD_TYPE_USER / namespc 18`。

**根因**：Intel 蓝牙在 macOS 13 上的已知唤醒 bug（OpenIntelWireless #417），
旧版 IntelBTPatcher 没修复；再叠加"1 分钟就睡"的 pmset 配置，睡醒循环直接点炸。

**解决**
1. IntelBTPatcher 升到含修复版本（本机 2.5.0）；
2. kext 顺序：`IntelBluetoothFirmware → IntelBTPatcher → BlueToolFixup`；
3. **完全关机冷启动**（热重启会残留不兼容固件）；
4. 修正睡眠参数（K08）；
5. 兜底：Bluesnooze（睡前关蓝牙，唤醒再开）。

**教训**
> `IntelBluetoothInjector.kext` 在 Monterey 之后**必须移除**；它是无代码 kext，
> `kextstat` 里看不到，很容易漏。

### K07 · 触控板完全没反应（三层坑）

**现象**：`ApplePS2SynapticsTouchPad` 节点在、属性齐全，但**没有任何 HID 输出**；
`VoodooRMI` / `RMISMBus` 在 config 里启用，`kmutil showloaded` 里却根本没有。

**根因（三层）**
1. **类名冲突**：厂商 `VoodooSMBus.kext` 是 611KB 的"合并版"（官方 300KB），
   自带 `TrackpointDevice` 类，和 `VoodooInput` 撞车：
   ```
   OSMetaClass: ... class TrackpointDevice is a duplicate
   Kext me.kishorprins.VoodooInput did not start (0xdc00400a)
   Couldn't alloc class "VoodooInput"
   ```
2. VoodooInput 起不来 → `VoodooPS2Trackpad` 没有 MT2 输出通道 → 触控板哑巴；
3. VoodooRMI 也依赖 VoodooInput 的类 → 一起起不来。
   （`RMISMBus` 只匹配 SMBus 地址 44/0x2C，本机枚举到 21，双保险失败。）

**解决**：只保留 PS2 链路 —— VoodooPS2Controller + VoodooInput + Keyboard/Mouse/Trackpad 开；
VoodooSMBus / VoodooRMI / RMISMBus 全关。

**教训（最重要的一条）**
> **判断触控板是否工作，不能看 `ioreg ... | grep -c IOHIDDevice` —— 这个值永远是 0。**
> VoodooInput 把 HID 设备挂在 VoodooInput 那一层。正确判据：实际手感 +
> `ioclasscount | grep -E "AppleMultitouchDevice|VoodooInput"`。

> 官方 VoodooSMBus 版本差异：**v1.0 干净**，v2.1 / v2.2 都带 `TrackpointDevice` → 冲突。

### K09 · 没声音：layout 用的是华硕的配置

**现象**：AppleHDA / AppleALC 都在，音频设备齐全，音量 65 未静音，`afplay` 不报错，
**但扬声器一点声音都没有**。

**根因**：实际生效 `alc-layout-id = 14`，而 layout 14 = **ASUS UX430UA 的 ALC295 配置**，
引脚映射和 HP Pavilion 完全不是一套 → 声音被送到不存在的引脚。

**解决**：`DeviceProperties → PciRoot(0x0)/Pci(0x1f,0x3)`：`layout-id = 24`、`alc-layout-id = 24`。

**ALC295 候选 layout**

| layout | 来源 | 适用 |
|---|---|---|
| **24** | zty199 | **HP Pavilion / OMEN-2（本机）** |
| 28 | vusun123 | Skylake HP Pavilion |
| 1 | Damon | HP Envy x360 15-bp107tx |
| 23 | Lancet-X | HP OMEN 15-AX000 |
| 3 / 13 / 15 / 21 | 多人 | 通用 ALC295/ALC3254 |

**教训**
> "有音频设备" ≠ "有声音"。必须实际放一首歌。声卡问题九成是 layout 选错。

### K10 · Type-C 插手机枚举失败

```
HS04@14400000: AppleUSBHostPort::createDevice: failed to create device (0xe00002bc)  (循环)
```
**根因**：端口正常，失败在设备/线材侧——充电线没有数据线 / 手机"仅充电" / 正反插方向。

**处置**：翻转 180°、换数据线、手机切 MTP；USB 映射里 HS04 标 9 (Type-C)。

**这台机器的 Type-C 边界**

| 用途 | 结论 |
|---|---|
| USB 数据 | ✅ 标准 XHCI，不需要驱动 |
| PD 充电 | ✅ 由 EC/BIOS 处理 |
| 视频输出 | ❌ 无 DP Alt Mode |
| 雷电 / USB4 | ❌ 无硬件 |

## 阶段 5 · 系统与电源

### K08 · 睡眠参数是"1 分钟就睡"

```
pmset -g custom:
AC:      sleep 1   displaysleep 10  womp 1  powernap 1  proximitywake 1
Battery: sleep 1   displaysleep 2
```
比屏幕休眠还早 → 频繁睡/醒，放大蓝牙唤醒 bug。

```bash
sudo pmset -a sleep 15 displaysleep 10 disksleep 10
sudo pmset -a womp 0 powernap 0 proximitywake 0
```

### K11 · 时间差 16 小时：时区被设成了美国太平洋时间

**根因**：macOS 定位只有两条路——GPS（笔记本没有）+ **Wi-Fi 热点数据库**。
itlwm 是以太网形态，系统里没有 Wi-Fi 接口 → 定位永远失败 →
"自动设置时区"回落到苹果总部所在地（库比蒂诺）。

```bash
sudo systemsetup -settimezone Asia/Shanghai
sudo systemsetup -usingnetworktime on
sudo defaults write /Library/Preferences/com.apple.timezone.auto Active -bool false
```

**教训**
> Intel 网卡方案下，定位服务永远不可用：天气、查找我的、Safari 定位都一样。
> 时钟本身是准的（NTP 正常），别去折腾时间服务器。

### K12 · 提示"宗卷哈希不匹配"

**含义**：SSV（签名系统宗卷）完整性校验没通过。系统卷是只读快照，里面有哈希树。

**为什么这台会报（但盘是好的）**：
`diskutil apfs list` 显示 Sealed: Yes；但黑苹果必须关 Authenticated Root
（`csr-active-config = 0x0A03`），否则 kext 注入不了；再加上 OC 注入 + SMBIOS 改动，注定对不上。

**影响**：只影响系统更新 / Safari 更新，不影响开机、数据、日常使用。

**处置**
- ❌ 别用「磁盘工具 → 急救」去"修"系统宗卷（很容易搞到起不来）
- ❌ 别走 OTA 更新
- ✅ 要更新用完整安装包重装/升级

### K13 · boot-args 一直是调试状态

`-v debug=0x100 keepsyms=1`：开机滚屏、日志被刷满。排障期有用，**稳定后清掉**，最多留 `keepsyms=1`。

### K14 · SMBIOS 与 CPU 代差不匹配

`MacBookPro15,2` 是 2018 款 Coffee Lake（Iris Plus 655），而 CPU 是 Kaby Lake-R 的 i5-8250U。
- 能跑，XCPM 正常；
- AGDP 按 15,2 的 board-id 走，**外接 HDMI 可能黑屏/无声**，需要实测；
- 好处：支持到 Sonoma/Sequoia，以后升级不用换 SMBIOS。

**教训**
> 换 SMBIOS 会让 iCloud/iMessage 需要重新登录，**没有明确问题就别动**。

### K15 · ACPI 每 30 分钟报一次 `CMS0 / SystemCMOS`

```
ACPI Error: No handler for Region [CMS0] [SystemCMOS]
```
无害（DSDT 里的 CMOS 操作区域没人处理）。强迫症可以加 SSDT-RTC0，否则忽略。

## 阶段 6 · 硬件限制：这些不是 bug，别白折腾

| 功能 | 状态 | 原因 |
|---|---|---|
| 隔空投送 / 接力 / 通用控制 / 随航 | ❌ | Intel 网卡没有 AWDL |
| Wi-Fi 原生菜单 / 控制中心 | ❌ | itlwm 是以太网形态，靠 HeliPort |
| 定位 / 自动时区 / 天气定位 | ❌ | 没有 CoreWLAN，locationd 拿不到位置 |
| 读卡器 | ❌ | Realtek 读卡器 macOS 无驱动 |
| GPS | ❌ | 笔记本没有 GPS，Mac 全系都没有 |
| Thunderbolt / USB-C 视频输出 | ❌ | 该机型无雷电、无 DP Alt Mode |
| OTA 系统更新 | ⚠️ | SSV 校验会让更新失败 |
| 与其它蓝牙设备共存 | ❌ | Intel 方案官方明确不支持 |

## 阶段 7 · 装完之后：远程与被控

### R01 · macOS 原生"屏幕共享"默认是关的

系统设置 → 通用 → 共享 → 打开「屏幕共享」/「远程管理」，
并在「隐私与安全性 → 辅助功能 / 录屏与系统录音」里给对应进程授权。

### R02 · UU远程（网易）在 Mac 上被控，缺一不可的四步

1. 客户端 →「设置 → 安全」→ 开启**允许本设备被控**
2. 系统设置 → 隐私与安全性 → **辅助功能**：勾选 UU远程
3. 系统设置 → 隐私与安全性 → **录屏与系统录音**：勾选 UU远程
4. **完全退出客户端再重开**（不是关窗口）

官方说明：`https://uuyc.163.com/guide/macos.html`

### R03 · 客户端报「本地运行环境异常 / 错误码 201004」

**含义**：客户端要在本机起一个隔离沙箱（本地 Python 运行时 + 工具链），
它初始化失败时，任何走"本地电脑"的请求都会立刻报这个码。

**排查顺序（按命中率）**
```bash
sysctl kern.hv_support      # 0 = 虚拟化不可用，沙箱起不来（BIOS 里开 VT-x/VTd）
df -h /                     # 空间不足会解压失败
ls -ld ~/Library/Application\ Support/LarkShell
du -sh ~/Library/Application\ Support/LarkShell/sandbox_runtime
```
- 权限：系统设置 → 隐私与安全性 → **完全磁盘访问权限**，勾选客户端
- 网络：初始化要拉组件，全局代理容易超时，先关代理
- 装坏了的兜底（可逆）：
  ```bash
  mv ~/Library/Application\ Support/LarkShell/sandbox_runtime \
     ~/Library/Application\ Support/LarkShell/sandbox_runtime.bak
  ```
  重开客户端会重新下载；成功后再删 `.bak`
- 临时可用：把输入框左下角的「本地电脑」切成「云端」

## 阶段 8 · 元教训（比具体问题更值钱）

1. **"设备存在"不等于"功能正常"**
   声卡有设备但没声音（layout 错）；触控板有节点但没事件（类冲突）；
   Wi-Fi 通了但没有管理界面（itlwm 形态）。
   → **每个功能都要用真实操作验证**：放歌、划触控板、打开网页、传文件。

2. **判据要选对，否则会误判**
   触控板看 `IOHIDDevice` 子节点 = 永远 0；
   引导在不在硬盘，要看 ESP 里有没有 `EFI/OC/OpenCore.efi`，不是看 `nvram efi-boot-device`。

3. **kext 冲突的典型信号**
   `OSMetaClass: ... is a duplicate`、`did not start`、`Couldn't alloc class`；
   config 里启用、`kmutil showloaded` 里看不到的 kext —— 基本就是加载失败。

4. **厂商的"傻瓜包"要当心**
   说 ESP 干净，实际有 Windows 残留；说触控板配好了，实际 kext 互相冲突；
   说 layout 14，实际那是对华硕的配置。→ 拿到别人的 EFI，**必须逐项验证**。

5. **顺序很关键**
   先装 HeliPort 再删 WiFiConfig；先修 USB/蓝牙再调睡眠；先冷启动再判断蓝牙是否修好。

6. **改配置前先备份，改完先校验**
   `config.plist.before-*`、`Kexts-disabled/`；`plutil -lint config.plist`。

7. **自动化必须留日志**
   驱动别人的交互式 CLI，没有问答日志就没法维护（见 B05）。

## 附录 · 常用诊断命令速查

```bash
# 已加载的第三方 kext
kmutil showloaded | grep -v com.apple

# 某个 kext 是否真的加载（config 启用但这里没有 = 加载失败）
kmutil showloaded | grep -iE "voodoo|rmi|intelbluetooth|itlwm"

# 内核启动日志里的 kext 错误
log show --start "$(date -j -f '%s' $(sysctl -n kern.boottime | awk '{print $4}') '+%Y-%m-%d %H:%M:%S')" \
         --predicate 'process == "kernel"' | grep -iE "kext|OSMetaClass|Couldn't alloc"

# 显卡
system_profiler SPDisplaysDataType

# 声卡（要看 layout-id！）
ioreg -r -n HDEF -l | grep -iE "layout|device-id"
system_profiler SPAudioDataType

# 网卡 / Wi-Fi
system_profiler SPAirPortDataType
ioreg -r -c itlwm -l | grep -E "WiFiConfig|IOMACAddress"

# 蓝牙
system_profiler SPBluetoothDataType
ioreg -r -c IntelBluetoothFirmware -l | head

# USB 端口与类型
ioreg -r -c AppleUSBXHCIPort -l | grep -E '"port"|"UsbConnector"'

# 触控板（别看 IOHIDDevice 子节点）
ioclasscount | grep -E "AppleMultitouchDevice|VoodooInput|ApplePS2Synaptics"

# 电源 / 时区 / 系统宗卷
pmset -g custom
readlink /etc/localtime
diskutil apfs list | grep -E "Sealed|Snapshot"
```
