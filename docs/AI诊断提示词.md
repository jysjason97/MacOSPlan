# AI 诊断提示词

> 这套提示词是这次装机过程中真实用出来的：把「现象 + 判据 + 命令输出」喂给 LLM，
> 让它给**可验证的假设**，而不是给一堆"可能是驱动问题"的空话。
>
> 适用：DeepSeek Harness / 任意支持长上下文的模型。装完系统之后在 Mac 上跑，
> 也可以在 Windows 端用它分析启动盘制作日志。

---

## 使用原则

1. **一次只问一个问题**。把"没声音 + 触控板不动 + 蓝牙崩"一起问，得到的答案一定是糊的。
2. **必须贴证据**。现象描述 + 命令输出 + 你改过什么（越具体越好）。
3. **要求给判据**。让模型说"用哪条命令确认这个假设"，而不是直接给结论。
4. **禁止它猜版本号**。kext 版本、layout id 这类，必须让它说明来源或让你去查。

## P0 · 全局系统提示词（每次对话先发这段）

```text
你是一名黑苹果（OpenCore）排障工程师。你的任务不是安慰我，而是帮我定位到具体的一行配置或一个 kext。

必须遵守：
1. 先给「最可能的 3 个原因」，按概率排序，每个原因配一条能证伪它的命令。
2. 不允许把"更新驱动""重装系统"作为首选建议。
3. 不允许编造 kext 版本号、layout-id、SMBus 地址；不确定就说"需要查证"。
4. 区分「设备存在」和「功能可用」：有节点不等于有输出。
5. 每次回答结尾给一个「下一步只做这一件事」的清单，最多 3 条。

我的机器（按实际替换）：
- 机型：HP Pavilion 14-ce0xxx / BIOS Insidse F.23
- CPU：i5-8250U（Kaby Lake-R） / 核显：UHD 620 (8086:5917)
- 系统：macOS Ventura 13.7.8 / OpenCore 1.0.9 / SMBIOS MacBookPro15,2
- 网卡：Intel 9560（itlwm 2.3.0） / 声卡：ALC295 / 触控板：Synaptics SMBus
```

## P1 · 可行性判定（装机前）

```text
根据下面的硬件信息，判断这台机器能不能装 macOS，并按三层给结论：
1) 硬门槛：CPU 代次 + 图形是否可驱动；
2) 体验层：Wi-Fi/蓝牙/读卡器/外接显示哪些注定不可用；
3) 明确劝退项（如果有）。

硬件：
- CPU：{型号}
- 显卡：{核显 + 独显型号与设备 ID}
- 无线：{型号 + 设备 ID}
- 声卡：{codec}
- 硬盘：{型号 + 接口}
- BIOS：{版本 + 是否 UEFI}

要求：给出「推荐版本 + 为什么不是更高版本」，并列出必须接受的的功能缺失。
不要给"应该可以"这种结论。
```

## P2 · 启动盘做好了，但 OpenCore 菜单里没有安装项

```text
现象：U 盘启动后进入 OpenCore 菜单，只看到 Windows（或只看到 ___U___(dmg) 这种下划线名字），
没有 macOS 安装项。按空格展开隐藏项也不出来。

已知：
- EFI 来自 OpCore-Simplify，config.plist 我改过 {列出改动}
- 恢复镜像来自 macrecovery，BaseSystem.dmg 大小 {大小}
- U 盘 {容量}GB，FAT32，卷标 {卷标}

请按「最可能 → 最不可能」给 3 个原因，每个原因给：
1) 判断依据（我该看 config 的哪个键 / 哪条命令）
2) 修复动作（精确到键名和值）
3) 修完如何验证

提示：先考虑 Misc > Security 下的三个键，再考虑卷标字符集。
```

> 实战结论：这台机器是 `DmgLoading=Signed` 把恢复项静默过滤了，改 `Any` 后出现；
> 同时卷标是中文，OpenCanopy 没有中文字形 → 显示成 `___U___(dmg)`。

## P3 · 装完第一次进系统：逐项体检

```text
我刚装完 macOS，请给我一份体检清单，按「不检查就会翻车」的顺序排列。
每项包含：检查命令 + 正常值 + 异常时的修复动作。

重点覆盖：
1) 硬盘 ESP 里到底有没有 OpenCore（拔 U 盘能不能开机）
2) 启动项是否自动注册（LauncherOption）
3) 声卡 layout 是否匹配本机（不是文档写的那个）
4) USB 端口映射是否真的生效（UsbConnector 属性）
5) 蓝牙 kext 顺序 / 是否有 IntelBluetoothInjector 残留
6) pmset 睡眠参数
7) 时区是否被自动设成美国

输出成表格，不要散文。
```

## P4 · 单点故障：没声音

```text
现象：音频设备齐全，音量未静音，afplay 不报错，但扬声器完全没有声音。

证据：
- 声卡 codec：ALC295
- ioreg -r -n HDEF -l 输出：{粘贴}
- system_profiler SPAudioDataType：{粘贴}
- 我用的是 layout-id {N}

请判断：
1) 这是 layout 选错，还是 AppleALC 没加载，还是引脚映射问题？
2) 分别用什么命令区分？
3) 如果是 layout，按「最可能适配这台机器」的顺序列 3 个候选，并说明依据。
```

## P5 · 单点故障：触控板没有任何反应

```text
现象：ioreg 里能看到 ApplePS2SynapticsTouchPad 节点，属性也齐（Intertouch Support = Yes），
但触控板不发任何事件。config 里 VoodooRMI/RMISMBus 是启用的，kmutil showloaded 里却看不到。

请按这个顺序分析：
1) 是不是 kext 类名冲突（看内核日志 OSMetaClass / did not start / Couldn't alloc class）
2) 如果是冲突，哪两个 kext 在抢同一个类名？
3) PS2 / I2C / SMBus 三条链路应该保留哪一条，为什么？
4) 判断触控板是否工作的正确判据是什么（注意：不要用 IOHIDDevice 子节点计数）
```

## P6 · 蓝牙睡醒后崩溃循环

```text
现象：/Library/Logs/DiagnosticReports 里 20+ 个 bluetoothd 崩溃，集中在睡醒后的几分钟。
崩溃类型：EXC_GUARD / GUARD_TYPE_USER / namespc 18。

已知：Intel 9560，kext 是 IntelBluetoothFirmware + IntelBTPatcher + BlueToolFixup。

请回答：
1) 这是已知 bug 吗？对应哪个 issue？
2) 是 BTPatcher 版本问题、kext 顺序问题、还是睡眠参数放大了它？
3) 给出「先改哪一个、怎么验证修好了」的顺序，不要一次让我改五样东西。
```

## P7 · 决策类：要不要升级 / 要不要换硬件

```text
我现在的状态是 {系统版本 + 已工作的功能 + 已知不可用功能}。
我在考虑 {升级到新版本 / 换网卡 / 换 SMBIOS}。

请按「收益 / 风险 / 可回退性」三维度评估，并明确告诉我：
1) 最坏情况下我会失去什么（能否回到现在的状态）
2) 有没有更便宜的替代方案
3) 如果要做，第一步的最小验证是什么
```

## P8 · 让 AI 读日志（最有效的一种用法）

```text
下面是开机后 5 分钟内的内核日志（已过滤 kext 相关）。请只做一件事：
找出所有「加载失败 / 类冲突 / 超时」的条目，按严重程度排序，
每条给出：涉及哪个 kext、失败码含义、对应的 config 修改建议。

不要总结日志里正常的部分，不要复述我已知的信息。

日志：
{粘贴 log show 的输出}
```

## 反面教材：这些提问方式一定拿不到有用的答案

| 提问 | 为什么没用 |
|---|---|
| "我的黑苹果没声音怎么办" | 没有 codec、没有 layout、没有日志，只能得到通用清单 |
| "帮我生成一个 EFI" | 模型不知道你的硬件，生成的配置一定是错的 |
| "是不是驱动问题？" | 封闭式提问，等于让它附和你的猜测 |
| "把每一步都告诉我" | 一次给 20 步，你无法判断哪一步起了作用 |

**正确姿势**：一次一个现象 + 一条命令输出 + 一个已经排除的可能。
